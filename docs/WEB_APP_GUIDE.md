# 안겹쳐 웹앱

같은 사람을 다시 만날 때 이전 착장과 겹치지 않도록 돕는 로컬 우선 PWA다. 사진·옷·착장·초안은 기존 angyeopchyeo IndexedDB 스키마를 유지한다. 서버 계정이나 자동 동기화는 없다.

## 사용 주소와 배포

https://damandeul.github.io/outfit-memory-app/

기존 주소를 유지해야 사용자가 기존 브라우저 데이터를 그대로 읽을 수 있다. GitHub main 브랜치 변경은 기존 deploy-pages 워크플로가 검증·빌드 후 배포한다. 환경 변수 VITE_BASE_PATH=/outfit-memory-app/를 유지한다. 다른 주소로 이동하거나 브라우저 데이터를 지우면 기존 로컬 기록을 읽을 수 없다. 업데이트를 받으려면 온라인에서 앱을 다시 열고 필요한 경우 새로고침한다.

## 검색

옷장은 이름·메모·카테고리·색상 별칭·계절을 검색한다. 예: 검정 여름 출근, ㄹㄴㅅㅊ. 여러 단어는 모두 일치해야 하며 띄어쓰기를 무시한 검색을 지원한다. 색상·계절·활성/보관 상태 필터와 초기화가 있다. 사계절 옷은 각 계절 필터에 포함된다. 기록은 만남·메모·날짜·당시 옷 이름/색상으로 찾으며 날짜 범위와 초안/착용 완료 필터가 있다. 오타 교정·의미 검색은 미구현이다.

## 기존 사용자의 사진 포함 백업

1. 기존에 사용하던 기기·브라우저·프로필로 위 주소를 연다. 브라우저 데이터는 삭제하지 않는다.
2. 설정 → 사진 포함 전체 백업을 선택하고 JSON 파일이 다운로드됐는지 확인한다.
3. 파일을 안전한 곳에 보관한다. 사진·옷·착장 사진·과거 snapshot 사진·초안·메모가 포함되며 암호화되지 않은 파일이다.
4. 다른 기기·브라우저에서 위 주소를 열고 설정 → 전체 백업 복원에서 파일을 선택한다.
5. 파일의 옷·착장 수를 확인하고 교체를 승인한다. 기존 데이터가 있다면 복원 전에 먼저 백업한다.
6. 복원된 사진과 기록을 확인한다.

백업은 v2 전체 파일을 사용한다. 사진 없는 이전 v1 메타데이터 파일은 복원하지 않는다. 최대 파일 크기는 200MB다. 손상된 구조·이미지 URL·중복 ID·불일치한 기록은 쓰기 전에 거부한다. 복원은 하나의 트랜잭션으로 진행해 쓰기 실패 시 원본을 유지한다. 백업 내보내기도 하나의 읽기 트랜잭션으로 일관된 시점을 읽는다.

## 개발과 검증

Node.js 환경에서 npm ci → npm run dev로 실행한다. 배포 빌드는 npm run build이다. 기존 테스트: npm test, npm run typecheck, npm run lint, npm run test:e2e. 자동 테스트는 실제 Android/iOS Safari 기기의 다운로드 UX를 대신하지 않는다.

## 남은 개선 우선순위

| 우선순위 | 근거 | 개선 |
|---|---|---|
| P1 | domain.ts recommend가 모든 조합을 생성 | 상위 후보만 계산하고 많은 옷을 등록한 경우 성능 검증 |
| P1 | meetingKey는 trim만 적용 | 만남 ID 및 사용자가 확인하는 중복 만남 병합 |
| P2 | App.tsx에 화면들이 모여 있음 | 화면별 컴포넌트 분리와 모달 포커스 복귀 점검 |
| P2 | 데이터는 로컬 저장이며 파일로 수동 이전 | 선택적 계정 동기화는 별도 요구사항으로 설계 |

기존 BUILD_REPORT, QA_REPORT, FINAL_HANDOFF는 기준 커밋 9bbc1f7의 이전 검증 기록이다. 현재 상태는 실제 검사 결과를 따른다. 개발 의존성 취약점 22건은 별도 업데이트 검토가 필요하며 강제 메이저 업데이트는 하지 않았다.

## 이번 웹앱 검증

타입 검사·린트·단위/화면 테스트 55개·모바일 Chromium E2E 16개가 통과했다. E2E에는 기존 스키마의 데이터 → 사진 포함 파일 다운로드 → 전체 삭제 → 파일 복원 → 사진/초안 확인 → 검색/필터 흐름이 포함된다. 기존 GitHub Pages 경로를 적용한 production 빌드도 통과했다. iOS Safari 등 실기기 검증은 별도로 필요하다.
